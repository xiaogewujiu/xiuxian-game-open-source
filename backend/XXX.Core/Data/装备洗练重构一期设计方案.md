# 装备洗练重构一期设计方案

## 一、目标结论

本方案重构当前装备洗练玩法，使洗练从“随机替换一组硬编码附加属性”升级为“可配置、可锁定、可取舍、有长期追求”的装备养成玩法。

一期目标是做出完整可玩的闭环：

| 模块 | 一期目标 |
|------|----------|
| 游戏端前端 | 玩家可以查看当前洗练词条、锁定词条、消耗洗练石和金币重新洗练、预览候选结果、接受或丢弃结果 |
| 后端服务 | 提供洗练预览、洗练生成、接受、丢弃接口，按配置扣除资源，持久化当前词条和候选词条 |
| 管理端 | 可以管理洗练系统开关、消耗公式、槽位词条池、词条品阶和权重 |
| 数据与运行时配置 | 启动时加载默认洗练规则，管理端保存后可刷新运行时规则 |

明确变更：

1. 不再使用单独的“锁定符”道具。
2. 锁定词条仍然保留，但通过增加洗练石消耗实现。
3. 洗练石消耗可配置，默认公式为：

```text
洗练石消耗 = 基础洗练石消耗 + 锁定词条数 × 每锁定一条额外洗练石消耗
```

默认值：

| 锁定数量 | 洗练石消耗 |
|----------|------------|
| 0条 | 1个 |
| 1条 | 2个 |
| 2条 | 3个 |
| 3条 | 4个 |

金币消耗仍作为经济回收项，由后台配置控制。

## 二、现状问题

当前装备洗练实现存在以下问题：

| 问题 | 影响 |
|------|------|
| 词条池硬编码 | 管理端无法调权重、调范围、调槽位产出 |
| 洗练立即覆盖原结果 | 玩家一次差结果会直接损失已有词条，体验挫败 |
| 消耗绑定旧材料 | 当前后端消耗狼牙，不符合装备洗练材料定位 |
| 锁定体系没有完整落地 | 玩家无法围绕好词条做长期追求 |
| 人物属性、装备槽位、技能效果没有联动规划 | 容易出现所有装备都追同一套最优词条，降低构筑差异 |
| 洗练结果和原始附加属性混在一起 | 后续评分、展示、继承、重铸都难区分来源 |

本方案把洗练拆成独立词条层，不破坏装备基础属性和旧附加属性。

## 三、多维度设计分析

### 3.1 人物属性维度

当前人物战斗属性可以按作用分为四类：

| 属性 | 名称 | 作用定位 | 洗练设计倾向 |
|------|------|----------|--------------|
| Type1 | 最大血量 | 生存核心 | 防具、鞋子、头盔高权重 |
| Type2 | 最大蓝量 | 技能续航 | 头盔、项链中权重 |
| Type3 | 物理攻击 | 物理输出核心 | 物理武器、戒指、项链高权重 |
| Type4 | 法术攻击 | 法术输出核心 | 法术武器、戒指、项链高权重 |
| Type5 | 物理防御 | 抗物理伤害 | 护甲、裤子、头盔高权重 |
| Type6 | 法术防御 | 抗法术伤害 | 护甲、裤子、头盔高权重 |
| Type7 | 速度 | 出手顺序和节奏 | 鞋子、项链高权重 |
| Type8 | 命中率 | 抵消闪避 | 武器、项链中权重 |
| Type9 | 闪避率 | 防御型概率收益 | 鞋子、护甲中权重 |
| Type10 | 暴击率 | 爆发输出入口 | 武器、戒指高权重 |
| Type11 | 暴击伤害 | 爆发输出放大 | 武器、戒指高权重，但数值要保守 |
| Type12 | 连击率 | 多段输出收益 | 武器、戒指中高权重 |
| Type13 | 反击率 | 防守反击构筑 | 头盔、护甲、裤子、鞋子中权重 |
| Type14 | 破甲率 | 克制高防敌人 | 武器、戒指中权重 |
| Type15 | 额外伤害 | 通用输出增益 | 武器、项链、戒指中权重 |

人物属性对洗练的要求：

1. 输出属性不能在所有槽位无脑出现，否则戒指、项链、武器以外的防具也会变成纯输出装备。
2. 百分比属性需要控制范围，暴击、连击、破甲、额外伤害会与技能倍率叠加，过高会导致后期伤害膨胀。
3. 生存属性要覆盖足够槽位，让坦克或抗压构筑有明确追求。
4. 速度和概率属性不能只按单条强弱判断，它们影响战斗节奏，应该通过槽位池和权重限制稀有度。

### 3.2 装备属性维度

装备由以下维度决定洗练表现：

| 维度 | 作用 |
|------|------|
| 槽位 Slot | 决定词条池基础方向 |
| 品质 Quality | 决定洗练词条数量 |
| 装备等级 Level | 决定整数属性数值范围和金币消耗 |
| 战斗风格 CombatStyle | 物理装备偏 Type3，法术装备偏 Type4 |
| 装备体系 GearArchetype | 防御装备偏物防或法防 |
| 强化等级 EnhanceLevel | 一期不直接影响洗练词条，避免洗练和强化耦合过重 |

槽位定位：

| 槽位 | 定位 | 推荐词条 |
|------|------|----------|
| 武器 | 主输出槽 | 物攻、法攻、命中、暴击、暴伤、连击、破甲、额外伤害 |
| 头盔 | 生存加续航 | 血量、蓝量、物防、法防、命中、反击 |
| 护甲 | 主防御槽 | 血量、物防、法防、闪避、反击 |
| 裤子 | 副防御槽 | 血量、物防、法防、速度、反击 |
| 鞋子 | 节奏与规避 | 速度、闪避、命中、反击、血量 |
| 项链 | 通用混合槽 | 命中、速度、蓝量、物攻、法攻、额外伤害 |
| 戒指 | 副输出槽 | 物攻、法攻、暴击、暴伤、连击、破甲、额外伤害 |

品质和条数：

| 装备品质 | 洗练词条数量 |
|----------|--------------|
| 1 普通 | 1条 |
| 2 优秀 | 2条 |
| 3 精良 | 3条 |
| 4 史诗 | 4条 |
| 5 传说 | 5条 |

一期按 `Math.Clamp(装备品质, 1, 5)` 计算条数。后续如果出现更高品质，可以通过配置扩展。

### 3.3 技能效果维度

洗练需要服务构筑，而不是只提供单纯数值堆叠。

| 技能或战斗效果 | 关联属性 | 洗练影响 |
|----------------|----------|----------|
| 物理技能 | Type3 | 物理武器和戒指更适合追物攻 |
| 法术技能 | Type4 | 法术武器和戒指更适合追法攻 |
| 高倍率单段技能 | Type10、Type11、Type14、Type15 | 暴击、暴伤、破甲、额外伤害收益高 |
| 多段或普攻流 | Type12、Type15、Type8 | 连击、额外伤害、命中收益更稳定 |
| 防守反击流 | Type1、Type5、Type6、Type9、Type13 | 生存、闪避、反击形成闭环 |
| 消耗型技能 | Type2 | 蓝量词条提高续航 |
| 先手控制或爆发 | Type7 | 速度词条提供节奏优势 |

平衡原则：

1. 武器和戒指承载主要输出词条。
2. 防具承载生存词条，允许少量概率防御词条。
3. 项链作为混合槽，提供构筑补足，不应比武器或戒指更强。
4. 百分比词条之间存在乘法放大，默认范围必须低于旧方案上限。

### 3.4 经济维度

洗练是一条长期材料消耗线，需要同时消耗道具和金币：

| 消耗 | 作用 |
|------|------|
| 洗练石 | 核心养成材料，控制洗练次数 |
| 金币 | 通用货币回收，避免金币长期通胀 |
| 锁定额外洗练石 | 让玩家为“保留好词条”付出更高边际成本 |

不引入锁定符的原因：

1. 降低背包材料复杂度。
2. 减少管理端和掉落配置成本。
3. 锁定成本仍然存在，且直接通过洗练石消耗表达，玩家更容易理解。

金币消耗公式：

```text
基础金币 = 基础金币消耗 + 装备等级 × 每级金币消耗
品质修正金币 = 基础金币 × 品质金币倍率
最终金币 = 品质修正金币 × (1 + 洗练次数 × 洗练次数金币成长百分比 / 100)
```

默认建议：

| 配置 | 默认值 |
|------|--------|
| 基础金币消耗 | 300 |
| 每装备等级金币消耗 | 25 |
| 品质金币倍率 | 1:1.0, 2:1.2, 3:1.5, 4:2.0, 5:2.8 |
| 洗练次数金币成长百分比 | 3 |

洗练石默认消耗：

| 配置 | 默认值 |
|------|--------|
| 基础洗练石消耗 | 1 |
| 每锁定一条额外洗练石消耗 | 1 |
| 最大锁定条数 | 3 |

## 四、核心玩法规则

### 4.1 当前词条与候选词条

洗练结果分为两层：

| 数据 | 说明 | 是否生效 |
|------|------|----------|
| 当前洗练词条 RerollStats | 玩家已经接受的洗练词条 | 生效，参与人物属性计算 |
| 候选洗练词条 RerollCandidate | 最近一次洗练生成但未接受的结果 | 不生效，仅展示 |

洗练流程：

1. 玩家打开装备洗练界面。
2. 后端返回当前词条、候选词条、消耗配置和最大锁定条数。
3. 玩家选择锁定当前词条中的若干条。
4. 点击洗练后扣除金币和洗练石。
5. 后端生成候选词条，当前词条不变。
6. 玩家可以选择接受候选结果，候选词条变为当前词条并生效。
7. 玩家也可以丢弃候选结果，当前词条不变，不返还消耗。

设计收益：

1. 玩家不会因为一次差结果立刻损失已有好词条。
2. 每次洗练仍然有消耗，候选结果不满意时沉没成本成立。
3. 接受和丢弃是明确决策，玩法体验更清晰。

### 4.2 锁定规则

锁定只针对当前已生效洗练词条。

规则：

1. 没有当前洗练词条时，不允许锁定。
2. 锁定索引用当前词条数组下标表示，从 0 开始。
3. 锁定索引必须存在，不能重复。
4. 锁定数量不能超过系统配置 `MaxLockedLineCount`。
5. 锁定词条在新候选结果中保持原下标和原数值。
6. 未锁定位置重新生成。
7. 如果已有候选结果但没有接受，继续洗练仍以当前已生效词条作为锁定来源，新候选会覆盖旧候选。

示例：

```text
当前词条：
0 物理攻击 +35
1 暴击率 +2.4%
2 速度 +8

锁定 [0, 1] 后洗练：
0 物理攻击 +35
1 暴击率 +2.4%
2 重新生成
```

### 4.3 洗练生成规则

生成步骤：

1. 根据装备品质确定目标词条数量。
2. 根据装备槽位、战斗风格、装备体系筛选可用词条池。
3. 对锁定位置直接复制当前词条。
4. 对未锁定位置按词条权重抽取属性类型。
5. 按品阶权重抽取词条品阶。
6. 在属性范围内随机基础值。
7. 按装备等级、品质、品阶倍率计算最终值。
8. 检查同属性重复数量限制，不满足则重抽。
9. 序列化为候选词条并保存。

整数属性计算：

```text
等级系数 = 1 + max(0, 装备等级 - 1) × 0.04
品质系数 = 1 + max(0, 装备品质 - 1) × 0.12
最终值 = round(随机基础值 × 等级系数 × 品质系数 × 品阶倍率)
```

百分比属性计算：

```text
最终值 = 随机基础值 × 品阶倍率
```

百分比属性不再额外乘装备等级，避免后期概率属性失控。

### 4.4 词条品阶

默认品阶：

| 品阶 | 名称 | 颜色 | 权重 | 数值倍率 |
|------|------|------|------|----------|
| 1 | 普通 | #9ca3af | 55 | 1.00 |
| 2 | 优秀 | #22c55e | 25 | 1.25 |
| 3 | 精良 | #38bdf8 | 12 | 1.55 |
| 4 | 史诗 | #a855f7 | 6 | 1.90 |
| 5 | 传说 | #f97316 | 2 | 2.30 |

品阶只影响单条词条颜色和数值，不改变装备自身品质。

### 4.5 重复词条限制

默认同一属性最多出现 1 次。管理端词条池可配置 `MaxDuplicateCount`，未来可以允许少数通用属性重复。

一期建议：

| 属性类型 | 默认重复上限 |
|----------|--------------|
| Type1-Type15 | 1 |

如果某槽位池过小导致重抽失败，服务端允许降级处理：

1. 优先从同槽位同风格池抽取。
2. 池不足时放宽 CombatStyle 条件。
3. 再不足时放宽 GearArchetype 条件。
4. 仍不足时允许重复，但记录日志。

## 六、数据结构设计

### 6.1 装备实例字段

在 `EquipmentInstanceEntity` 增加：

| 字段 | 类型 | 说明 |
|------|------|------|
| RerollStatsJson | string? | 当前已接受洗练词条 |
| RerollCandidateJson | string? | 最近一次候选洗练词条 |
| RerollCount | int | 已执行洗练次数 |
| RerollCandidateCreatedAt | DateTime? | 候选结果生成时间 |

保留 `BonusStatsJson`：

1. `BonusStatsJson` 继续表示装备原有额外属性或历史属性。
2. `RerollStatsJson` 表示新洗练玩法词条。
3. 人物属性重算时两者都叠加。

### 6.2 洗练词条 DTO

词条结构：

| 字段 | 说明 |
|------|------|
| Index | 词条位置 |
| StatType | Type1-Type15 |
| Description | 属性中文名 |
| Value | 前端展示值，百分比转为百分数 |
| RawValue | 后端真实值 |
| IsPercentage | 是否百分比属性 |
| Tier | 品阶 |
| TierName | 品阶名称 |

请求：

    "equipmentId": "xxx"

1. `RerollStatsJson = RerollCandidateJson`

1. 继续接受旧请求 `{ equipmentId }`。

3. 不再立即覆盖当前词条，而是生成候选词条。

## 十四、关键实现约束

1. 不要再把洗练结果写入 `BonusStatsJson`。
2. 不要引入锁定符。
3. 锁定只增加洗练石消耗。
4. 候选词条不参与人物属性计算。
5. 接受候选才会改变人物属性。
6. 旧 `/api/equipment/reroll` 接口保留兼容，但行为改为生成候选。
7. 管理端配置使用运行时快照，避免每次洗练都查完整配置表。
8. 默认规则必须能在数据库空表时兜底，避免启动后玩法不可用。

## 十五、与灵田规则的关系

“灵田规则”不是洗练玩法内容，只是本项目已有的一套运行时配置管理范例。

洗练规则实现时只借鉴它的工程模式：

1. 数据库存规则配置。
2. 启动时加载到运行时服务。
3. 管理端修改后刷新运行时配置。
4. 种子数据提供内置默认配置。

洗练本身不依赖灵田玩法，不会引入灵田系统规则。
