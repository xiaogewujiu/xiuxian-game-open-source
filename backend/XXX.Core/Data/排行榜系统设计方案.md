排行榜系统设计方案

## 背景与目标

排行榜系统是游戏社交竞争的核心功能，通过展示玩家排名激发竞争欲望，提供追求目标。本方案基于用户需求设计战力榜、等级榜、财富榜、击杀榜、伤害榜五大排行榜，构建完整的排行体系和奖励机制。

## 一、排行榜系统概览

### 1.1 核心设计原则

| 原则 | 说明 |
|------|------|
| 多维度评价 | 不同榜单体现不同维度的实力/成就 |
| 实时更新 | 关键榜单实时刷新，保证竞争感 |
| 参与激励 | 非顶尖玩家也有参与奖励 |
| 周期重置 | 部分榜单周期性重置，给新玩家机会 |

### 1.2 排行榜数据结构

```csharp
public class RankingData
{
    public RankingType Type { get; set; }         // 排行榜类型

public class RankingConfig
{
    public RankingType Type { get; set; }         // 排行榜类型

    public int RefreshInterval { get; set; }      // 刷新间隔（秒）
    public bool IsPeriodic { get; set; }          // 是否周期性重置
    public int ResetDay { get; set; }             // 重置日期（每月几号）
}
```

## 二、排行榜类型设计

### 2.1 战力榜（CombatPower）

**定义**：玩家综合战斗能力的评分排名

**战力计算公式**：
```
总战力 = 装备战力 + 属性点战力 + 技能战力 + 聚灵阵战力 + 其他系统战力

装备战力 = Σ(每件装备的评分)
属性点战力 = 已分配属性点 × 50
技能战力 = Σ(技能等级 × 100)
聚灵阵战力 = 聚灵阵总等级 × 500
灵宠战力 = 出战灵宠战力 × 0.3

战力权重分配：
- 装备战力：60%
- 属性点战力：15%
- 技能战力：10%
- 聚灵阵战力：10%
- 灵宠战力：5%
```

**更新规则**：
- 实时更新（战力变化立即更新）
- 永久榜单（不重置）
- 显示前100名 + 自己排名

### 2.2 等级榜（Level）

**定义**：玩家角色等级的排名

**排序规则**：
```
1. 等级高者优先
2. 等级相同则经验值高者优先
3. 经验相同则先达到者优先
```

**更新规则**：
- 实时更新
- 永久榜单
- 显示前100名 + 自己排名

**等级上限考虑**：
```
满级后（50级）：
- 可继续累积"巅峰等级"
- 巅峰等级也计入等级榜排序
- 格式：50级(巅峰X级)
```

### 2.3 财富榜（Wealth）

**定义**：玩家持有金币总量的排名

**财富计算**：
```
总财富 = 背包金币 + 仓库金币 + 装备价值折算 + 道具价值折算

装备价值 = 装备评分 × 100
道具价值 = 道具单价 × 数量
```

**更新规则**：
- 每小时更新一次
- 永久榜单
- 显示前50名 + 自己排名

### 2.4 击杀榜（KillCount）

**定义**：累计击杀怪物数量的排名

**击杀统计**：
```
计入统计的击杀：
- 地图探索击杀的野怪
- 副本击杀的怪物
- 活动击杀的怪物

不计入统计的击杀：
- PVP击杀（单独榜单）
- 训练假人
- 任务特殊怪物
```

**更新规则**：
- 实时更新
- 月度重置（每月1日）
- 显示前100名 + 自己排名

### 2.5 伤害榜（Damage）

**定义**：在特定玩法中造成的最高单次伤害排名

**榜单分类**：
| 子榜单 | 说明 | 记录方式 |
|--------|------|----------|
| 单次伤害榜 | 单次攻击造成的最高伤害 | 记录最高值 |
| 副本伤害榜 | 单次副本累计伤害 | 记录最高值 |
| 活动伤害榜 | 活动期间累计伤害 | 活动期有效 |

**更新规则**：
- 实时更新
- 月度重置（单次伤害榜永久保留）
- 显示前50名 + 自己排名

## 五、排行榜计算与更新

### 5.1 战力实时计算

```csharp
public long CalculateCombatPower(Player player)
{
    long power = 0;

    // 装备战力（60%权重）
    long equipmentPower = player.EquippedItems.Sum(e => e.GetScore()) * 60 / 100;
    power += equipmentPower;

    // 属性点战力（15%权重）
    long attributePower = player.AllocatedAttributePoints * 50 * 15 / 100;
    power += attributePower;

    // 技能战力（10%权重）
    long skillPower = player.Skills.Sum(s => s.Level * 100) * 10 / 100;
    power += skillPower;

    // 聚灵阵战力（10%权重）
    long arrayPower = player.FiveElementArray.TotalLevel * 500 * 10 / 100;
    power += arrayPower;

    // 灵宠战力（5%权重）
    long petPower = player.ActivePet?.CombatPower * 30 / 100 ?? 0;
    power += petPower;

    return power;
}
```

### 5.2 榜单更新策略

| 榜单类型 | 更新频率 | 更新方式 | 数据存储 |
|----------|----------|----------|----------|
| 战力榜 | 实时 | 战力变化时更新 | Redis + 数据库 |
| 等级榜 | 实时 | 等级变化时更新 | Redis + 数据库 |
| 财富榜 | 每小时 | 定时任务更新 | Redis + 数据库 |
| 击杀榜 | 实时 | 击杀时更新 | Redis |
| 伤害榜 | 实时 | 造成伤害时更新 | Redis |

### 5.3 性能优化

```
1. 使用Redis Sorted Set存储排行榜
   - 天然支持排序
   - 支持范围查询
   - 支持获取排名

2. 延迟写入数据库
   - 榜单数据先写Redis
   - 定时批量写入数据库
   - 减少数据库压力

3. 分页加载
   - 首次加载只显示前20名
   - 下拉加载更多
   - 减少数据传输

4. 缓存玩家排名
   - 玩家个人排名缓存5分钟
   - 减少实时计算
```

### 8.2 核心算法

```csharp
// 更新排行榜
public void UpdateRanking(RankingType type, string playerId, long score)
{
    string key = $"ranking:{type}";

    // 更新Redis Sorted Set
    Redis.SortedSetAdd(key, playerId, score);

    // 限制榜单大小（只保留前1000名）
    Redis.SortedSetRemoveRangeByRank(key, 0, -1001);

    // 异步更新数据库
    AsyncUpdateDatabase(type, playerId, score);
}

// 获取排名
public int GetRank(RankingType type, string playerId)
{
    string key = $"ranking:{type}";
    long? rank = Redis.SortedSetReverseRank(key, playerId);
    return rank.HasValue ? (int)rank.Value + 1 : -1;
}

// 获取前N名
public List<RankingData> GetTopN(RankingType type, int n)
{
    string key = $"ranking:{type}";
    var entries = Redis.SortedSetRangeByRankWithScores(key, 0, n - 1, Order.Descending);

    return entries.Select((entry, index) => new RankingData
    {
        Type = type,
        PlayerId = entry.Element,
        Score = (long)entry.Score,
        Rank = index + 1
    }).ToList();
}

// 发放榜单奖励
public void DistributeRewards(RankingType type)
{
    var topPlayers = GetTopN(type, 100);

    foreach (var player in topPlayers)
    {
        var rewards = GetRewardsByRank(type, player.Rank);
        foreach (var reward in rewards)
        {
            GiveReward(player.PlayerId, reward);
        }
    }
}
```

## 九、平衡性验证

### 9.1 战力榜分布预测

```
假设服务器10000名活跃玩家：

战力分布：
- 10万+战力：约10人（0.1%）
- 5-10万战力：约100人（1%）
- 3-5万战力：约500人（5%）
- 1-3万战力：约2000人（20%）
- 1万以下：约7390人（73.9%）

奖励覆盖：
- 前100名有奖励：覆盖到约3万战力
- 上榜有奖励：覆盖到约1万战力
- 约26%的活跃玩家能上榜

结论：榜单有区分度，同时保证足够参与度
```

### 9.2 奖励价值分析

```
月度总奖励支出（战力榜）：
第1名：2000灵石
第2名：1500灵石
第3名：1000灵石
4-10名：600×7 = 4200灵石
11-50名：300×40 = 12000灵石
51-100名：150×50 = 7500灵石
上榜：50×900 = 45000灵石（假设900人上榜）

总计：约73000灵石/月

对比月卡收入（假设1000人买月卡）：
月卡收入：30元×1000 = 30000元 = 300万灵石（按1元=100灵石）

比例：榜单支出约占总收入2.4%

结论：奖励成本可控，不会造成经济失衡
```
