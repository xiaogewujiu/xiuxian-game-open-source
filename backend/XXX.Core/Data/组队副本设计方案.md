组队副本设计方案

## 背景与目标

组队副本系统是多人协作的核心玩法，2-3名玩家组队挑战高难度副本，获得比单人游戏更丰厚的奖励。本方案设计副本难度分级、组队匹配机制、贡献度计算和分配规则，构建有趣的多人协作体验。

## 一、组队副本系统概览

### 1.1 核心设计原则

| 原则 | 说明 |
|------|------|
| 小队协作 | 2-3人小队，强调配合而非人数碾压 |
| 难度递进 | 多难度分级，满足不同实力玩家 |
| 贡献分配 | 按贡献度分配奖励，鼓励积极表现 |
| 社交体验 | 促进玩家互动，建立游戏社交关系 |

### 1.2 数据结构

```csharp
public class DungeonInstance
{
    public string DungeonId { get; set; }         // 副本实例ID
    public int TemplateId { get; set; }           // 副本模板ID
    public DungeonDifficulty Difficulty { get; set; } // 难度
    public List<DungeonMember> Members { get; set; } // 队伍成员
    public DungeonStatus Status { get; set; }     // 副本状态
    public DateTime StartTime { get; set; }       // 开始时间
}

public class DungeonMember
{
    public string PlayerId { get; set; }          // 玩家ID
    public string PlayerName { get; set; }        // 玩家名称
    public bool IsLeader { get; set; }            // 是否队长
    public long DamageDealt { get; set; }         // 造成伤害
    public long DamageTaken { get; set; }         // 承受伤害
    public long HealingDone { get; set; }         // 治疗量
    public int ContributionScore { get; set; }    // 贡献度评分
}

public enum DungeonDifficulty
{
    Normal = 1,       // 普通
    Hard = 2,         // 困难
    Hell = 3          // 地狱
}
```

## 二、副本设计

### 2.1 副本类型

| 副本ID | 副本名称 | 推荐等级 | 队伍人数 | 通关时间 |
|--------|----------|----------|----------|----------|
| 101 | 迷雾森林深处 | 10-20级 | 2-3人 | 10-15分钟 |
| 102 | 荒芜山脉洞穴 | 20-30级 | 2-3人 | 10-15分钟 |
| 103 | 烈焰谷核心 | 30-40级 | 2-3人 | 15-20分钟 |

| 105 | 五行禁地 | 50级 | 3人 | 20-30分钟 |

### 2.2 难度分级

| 难度 | 怪物强度 | 奖励倍率 | 推荐战力 |
|------|----------|----------|----------|
| 普通 | 100% | 100% | 当前等级标准战力 |
| 困难 | 150% | 150% | 标准战力×1.3 |
| 地狱 | 220% | 220% | 标准战力×1.8 |

### 2.3 副本机制

**BOSS机制（与普通战斗的区别）**：
```
1. 多阶段战斗
   - BOSS血量降至70%/40%/10%时切换阶段
   - 每阶段有新技能和机制

2. 团队技能
   - BOSS释放需要团队协作应对的技能
   - 如：一人被点名，队友需要救助

3. 环境机制
   - 场地中有需要躲避的AOE
   - 有需要利用的场景道具

4. 仇恨系统
   - BOSS会优先攻击仇恨最高的玩家
   - 需要合理控制仇恨分配
```

## 三、组队匹配机制

### 3.1 组队方式

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| 好友组队 | 邀请好友加入队伍 | 固定队伍、语音配合 |
| 宗门组队 | 邀请同宗门成员 | 宗门活动 |
| 快速匹配 | 系统自动匹配队友 | 随机组队、快速开始 |
| 招募频道 | 发布招募信息 | 特定需求队伍 |

### 3.2 快速匹配规则

```
匹配条件：
1. 等级匹配
   - 匹配等级差 ≤ 5级
   - 优先匹配同等级段

2. 战力匹配
   - 匹配战力差 ≤ 20%
   - 防止战力差距过大

3. 职业/流派平衡（可选）
   - 尽量匹配不同流派的玩家
   - 如：1输出+1辅助+1坦克

4. 等待时间
   - 最长等待3分钟
   - 超时自动扩大匹配范围
```

### 3.3 队伍管理

**队长权限**：
- 开始副本
- 踢出队员（投票制，需另一人同意）
- 调整队伍设置
- 分配模式选择

**队员权限**：
- 退出队伍
- 准备/取消准备
- 发送快捷消息

## 四、贡献度计算系统

### 4.1 贡献度构成

```
总贡献度 = 伤害贡献×40% + 承伤贡献×25% + 治疗贡献×25% + 其他贡献×10%
```

### 4.2 各项贡献计算

**伤害贡献**：
```
伤害贡献分 = (个人伤害 / 队伍总伤害) × 100

示例：
玩家A伤害：50000
玩家B伤害：30000
玩家C伤害：20000
总伤害：100000

玩家A贡献分：50
玩家B贡献分：30
玩家C贡献分：20
```

**承伤贡献**：
```
承伤贡献分 = (个人承伤 / 队伍总承伤) × 100

坦克承伤高，获得相应贡献
```

**治疗贡献**：
```
治疗贡献分 = (个人治疗 / 队伍总治疗) × 100

治疗职业主要通过此项获得贡献
```

**其他贡献**：
```
- 复活队友：+5分/次
- 解除控制：+3分/次
- 关键打断：+5分/次
- 救助被点名队友：+5分/次
```

### 4.3 贡献度修正

```
防刷机制：
- 伤害低于平均值50%：贡献度×0.5
- 挂机检测：无操作超过30秒，贡献度×0
- 离线惩罚：离线超过1分钟，贡献度×0

鼓励机制：
- 最高伤害：额外+10分
- 最高承伤：额外+10分
- 最高治疗：额外+10分
```

## 五、奖励分配机制

### 5.1 基础奖励池

| 难度 | 金币 | 经验 | 材料 | 装备 |
|------|------|------|------|------|
| 普通 | 5000 | 5000 | 5个 | 当前等级蓝装 |
| 困难 | 10000 | 10000 | 10个 | 当前等级紫装 |
| 地狱 | 20000 | 20000 | 20个 | 当前等级橙装 |

### 5.2 贡献度分配公式

```
个人奖励 = 基础奖励 × (个人贡献度 / 100) × 分配系数

分配系数：
- 贡献度 ≥ 80%：系数1.2（优秀）
- 贡献度 50-79%：系数1.0（正常）
- 贡献度 30-49%：系数0.8（较低）
- 贡献度 < 30%：系数0.5（极低）

保底机制：
- 最低获得基础奖励的30%
- 防止新人完全没收益
```

### 5.3 分配示例

```
场景：3人通关困难副本
基础奖励池：10000金币，10000经验

贡献度：
玩家A（输出）：45%
玩家B（坦克）：30%
玩家C（治疗）：25%

玩家A获得：
金币 = 10000 × 0.45 × 1.0 = 4500
经验 = 10000 × 0.45 × 1.0 = 4500

玩家B获得：
金币 = 10000 × 0.30 × 1.0 = 3000
经验 = 10000 × 0.30 × 1.0 = 3000

玩家C获得：
金币 = 10000 × 0.25 × 1.0 = 2500
经验 = 10000 × 0.25 × 1.0 = 2500

装备分配：
各自独立掉落，不受贡献度影响
```

### 5.4 额外奖励

**首通奖励**：
```
每个副本每个难度首次通关：
- 灵石×100

- 总伤害 > 标准值

奖励：
- 额外材料×50%

```

## 八、实现方案

```csharp
// 计算贡献度
public void CalculateContribution(DungeonInstance dungeon)
{
    long totalDamage = dungeon.Members.Sum(m => m.DamageDealt);
    long totalTaken = dungeon.Members.Sum(m => m.DamageTaken);
    long totalHeal = dungeon.Members.Sum(m => m.HealingDone);

    foreach (var member in dungeon.Members)
    {
        int damageScore = (int)((double)member.DamageDealt / totalDamage * 40);
        int takenScore = (int)((double)member.DamageTaken / totalTaken * 25);
        int healScore = (int)((double)member.HealingDone / totalHeal * 25);

        member.ContributionScore = damageScore + takenScore + healScore;
    }
}

// 分配奖励
public void DistributeRewards(DungeonInstance dungeon)
{
    var baseRewards = GetBaseRewards(dungeon.TemplateId, dungeon.Difficulty);

    foreach (var member in dungeon.Members)
    {
        float ratio = member.ContributionScore / 100f;
        float multiplier = GetMultiplier(member.ContributionScore);

        var personalRewards = new Rewards
        {
            Gold = (int)(baseRewards.Gold * ratio * multiplier),
            Exp = (int)(baseRewards.Exp * ratio * multiplier),
            Materials = (int)(baseRewards.Materials * ratio * multiplier)
        };

        // 保底
        personalRewards.Gold = Math.Max(personalRewards.Gold, (int)(baseRewards.Gold * 0.3));

        GiveRewards(member.PlayerId, personalRewards);

        // 独立掉落装备
        var equipment = GenerateEquipment(dungeon.TemplateId, dungeon.Difficulty);
        GiveItem(member.PlayerId, equipment);
    }
}
```

## 九、平衡性验证

### 9.1 收益对比

```
单人刷怪 vs 组队副本（30分钟）：

单人刷怪：
- 金币：约8000
- 经验：约8000
- 装备：约5件

组队副本（2次困难）：
- 金币：约15000（平均贡献）
- 经验：约15000
- 装备：约6件（品质更高）
- 材料：约20个

结论：组队副本收益明显高于单人，鼓励组队
```

### 9.2 难度平衡

```
困难难度：
- 怪物强度×1.5
- 需要基本配合
- 战力达标可通关

地狱难度：
- 怪物强度×2.2
- 需要熟练配合
- 战力达标且有策略才能通关

通关率预期：
- 普通：90%
- 困难：70%
- 地狱：40%
```
