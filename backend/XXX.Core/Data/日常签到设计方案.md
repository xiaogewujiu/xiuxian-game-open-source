日常签到系统设计方案

## 背景与目标

日常签到系统是提升玩家日活跃的核心功能，通过提供稳定的每日奖励，鼓励玩家养成每日登录游戏的习惯。本方案设计完整的签到周期、奖励梯度、补签机制，构建可持续的签到激励体系。

## 一、签到系统概览

### 1.1 核心设计原则

| 原则 | 说明 |
|------|------|
| 低门槛 | 只需登录即可签到，无需完成任务 |
| 高价值 | 奖励具有吸引力，让玩家觉得值得登录 |
| 累积激励 | 连续签到奖励递增，断签有惩罚但不致命 |
| 补签机制 | 允许补签，降低玩家因特殊情况断签的挫败感 |

### 1.2 签到数据结构

```csharp
public class CheckInData
{
    public string PlayerId { get; set; }          // 玩家ID
    public DateTime LastCheckInDate { get; set; } // 最后签到日期
    public int CurrentStreak { get; set; }        // 当前连续签到天数
    public int MaxStreak { get; set; }            // 历史最大连续天数
    public int TotalCheckIns { get; set; }        // 累计签到总天数
    public List<int> RewardedDays { get; set; }   // 本月已领取奖励的天数
    public int RemakeCount { get; set; }          // 本月剩余补签次数
}

public class CheckInReward
{
    public int Day { get; set; }                  // 第几天
    public List<RewardItem> Rewards { get; set; } // 奖励列表
    public bool IsSpecial { get; set; }           // 是否特殊奖励（7/14/21/28天）
}

public class RewardItem
{
    public int ItemId { get; set; }               // 道具ID
    public int Count { get; set; }                // 数量
    public RewardType Type { get; set; }          // 奖励类型
}
```

### 4.3 断签处理

**断签判定**：
```
连续签到在以下情况会中断：
1. 超过24:00未签到
2. 主动选择不签到（不常见）

断签惩罚：
- 连续天数重置为0
- 但累计签到天数保留
- 本月已领取奖励保留
```

**断签保护机制**：
```
VIP玩家特权：
- VIP1-3：每月1次免费补签
- VIP4-6：每月2次免费补签
- VIP7+：每月3次免费补签

月卡用户特权：
- 激活月卡期间：每日额外奖励翻倍
```

### 8.2 核心算法

```csharp
// 每日签到
public CheckInResult DailyCheckIn(string playerId)
{
    var data = GetCheckInData(playerId);
    var today = DateTime.Today;

    // 检查今天是否已签到
    if (data.LastCheckInDate == today)
        return CheckInResult.AlreadyCheckedIn;

    // 计算连续天数
    if (data.LastCheckInDate == today.AddDays(-1))
    {
        data.CurrentStreak++;  // 连续签到
    }
    else
    {
        data.CurrentStreak = 1; // 断签重置
    }

    // 获取今日奖励
    int dayOfMonth = today.Day;
    var rewards = GetDailyRewards(dayOfMonth);

    // 发放奖励
    foreach (var reward in rewards)
    {
        GiveReward(playerId, reward);
    }

    // 更新数据
    data.LastCheckInDate = today;
    data.TotalCheckIns++;
    data.RewardedDays.Add(dayOfMonth);

    // 检查连续签到奖励
    CheckStreakRewards(playerId, data.CurrentStreak);

    // 检查累计签到奖励
    CheckTotalRewards(playerId, data.TotalCheckIns);

    SaveCheckInData(data);

    return CheckInResult.Success;
}

// 补签
public RemakeResult RemakeCheckIn(string playerId, int day)
{
    var data = GetCheckInData(playerId);

    // 检查补签次数
    if (data.RemakeCount <= 0)
        return RemakeResult.NoRemakeCount;

    // 检查是否已签到
    if (data.RewardedDays.Contains(day))
        return RemakeResult.AlreadyCheckedIn;

    // 扣除补签消耗
    if (!ConsumeCurrency(playerId, CurrencyType.LingStone, 50))
        return RemakeResult.InsufficientCurrency;

    // 发放奖励
    var rewards = GetDailyRewards(day);
    foreach (var reward in rewards)
    {
        GiveReward(playerId, reward);
    }

    // 更新数据
    data.RewardedDays.Add(day);
    data.RemakeCount--;

    // 修复连续天数（如果补签的是昨天）
    if (day == DateTime.Today.Day - 1)
    {
        data.CurrentStreak++;
    }

    SaveCheckInData(data);

    return RemakeResult.Success;
}

// 月度重置
public void MonthlyReset(string playerId)
{
    var data = GetCheckInData(playerId);

    // 保留累计数据
    data.RewardedDays.Clear();
    data.RemakeCount = 3;  // 重置补签次数
    // CurrentStreak 保持或根据情况处理

    SaveCheckInData(data);
}
```

## 九、平衡性验证

### 9.1 奖励节奏分析

```
第1-7天：基础资源积累期
- 奖励以金币、药水为主
- 帮助新手玩家度过初期

第8-14天：养成材料积累期
- 强化石、洗练石开始出现
- 支撑装备养成需求

第15-21天：高级资源期
- 更多灵石、高级材料
- 提升玩家粘性

第22-28天：冲刺期
- 奖励价值最高
- 鼓励玩家完成整月签到
```

### 9.2 与付费平衡

```
月度签到总灵石：500
月卡每日灵石：100×30 = 3000

比例：免费:付费 = 1:6

结论：
- 免费玩家通过签到获得基础资源
- 付费玩家获得显著加成
- 差距合理，不破坏平衡
```

### 9.3 断签影响分析

```
假设玩家每月断签2天：
- 损失约2天的基础奖励
- 但不影响连续签到的周奖励
- 可以通过补签弥补（消耗150灵石）

结论：偶尔断签损失可控，不会严重影响玩家体验
```
